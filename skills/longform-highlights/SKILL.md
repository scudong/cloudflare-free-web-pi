# 长文要点

把一篇长文压成五条要点，每条都能回到原文核对。适合读书笔记、长报道、播客文字稿和内部文档。

## 什么时候用它

- 你收藏了一篇长文，只想记住其中真正有用的五件事。
- 你要在读书会或周会上分享一篇文章，需要带原文依据的提纲。
- 你在判断一篇文章值不值得读全文，想先看它的信息密度。

## 输入

用户会贴长文正文，可能说明用途或关注主题。按下面的方式处理：

1. 正文完整时直接提炼；只有标题或链接时，请用户贴正文。
2. 用户给了关注主题时，优先选与该主题相关的要点，但仍保持五条。
3. 正文是访谈或播客文字稿时，定位句带上发言人和大致位置。
4. 正文超过一万字时，先按小节各选一条候选，再合并成五条，避免只读开头。

## 选点标准

按下面的优先级挑，不要平均分配篇幅：

1. **新信息**：读者原本不知道的事实、数据、机制。
2. **反直觉**：与常见做法相反、且作者给了理由的判断。
3. **可行动**：读者今天就能照做的步骤、清单或判断方法。
4. **关键数字**：能改变结论的规模、比例、时间。
5. **边界**：作者明确说「不适用」或「会失效」的条件。

同一件事在不同段落重复出现时只选一次；纯情绪表达、修辞、名人引语不选，除非它本身就是核心论点。

## 写作规则

- 固定五条。原文确实支撑不了五条时，写「原文只支撑 N 条」，然后列出 N 条，不凑数。
- 每条一行要点，不超过 45 字，用自己的话概括，不直接抄整段。
- 每条必须附一句原文定位句，放在「」里，逐字引用，不改写、不省略关键限定词。
- 定位句尽量带位置：小节标题、第几段、时间戳或发言人。
- 再补一句「为什么重要」，不超过 30 字，说明它改变了什么判断或动作。
- 不把作者的推测写成事实；推测要在要点里标「作者判断」。
- 不按文章顺序机械摘抄；按重要性排序。
- 五条之间不重复，不把同一条拆成两条。

## 输出格式

```text
# <文章标题> 要点

1. <要点>
   原文：「<逐字定位句>」（<小节/段落/时间戳>）
   为什么重要：<一句话>

2. <要点>
   原文：「<逐字定位句>」（<位置>）
   为什么重要：<一句话>

3. <要点>
   原文：「<逐字定位句>」（<位置>）
   为什么重要：<一句话>

4. <要点>
   原文：「<逐字定位句>」（<位置>）
   为什么重要：<一句话>

5. <要点>
   原文：「<逐字定位句>」（<位置>）
   为什么重要：<一句话>
```

## 边界情况

- **原文重复度高**：合并同义段落，只保留信息量最大的一处引用。
- **原文以故事为主**：选推动情节转折的事实和人物选择，不选环境描写。
- **原文有大量数据**：只保留能改变结论的数字；同一组数字不拆成多条。
- **定位句过长**：截取包含主谓宾的片段，用省略号标出删减，不能改变原意。
- **用户要求十条**：先给标准五条，再另起「补充五条」，并说明补充部分优先级较低。
- **无法确认原文**：明确说「正文不完整，以下要点只覆盖已提供部分」。

## 示例对话

```text
用户：这篇八千字的行业报告，帮我提五条要点，下周读书会用。
助手：已按重要性排出五条，每条都带原文定位句。
第一条讲需求增速从 18% 降到 6%，定位句在「市场概况」第二节。
第二条讲头部厂商靠提价维持收入，作者判断，不是官方数据。
第三条是可行动项：报告建议把续费口径从席位数改成活跃账号数。
第四条给了一个边界：该结论只适用于客单价低于一万元的产品。
第五条讲渠道成本上升，原文给了两张表的对比。
五条都在，没有为凑数加入泛泛而谈的建议。
```
