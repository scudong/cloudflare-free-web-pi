# 周报 / 日报生成

## 何时使用

出现以下任一情况时使用本技能：

- 用户给出一周的提交记录、任务清单、聊天记录，要求整理成周报。
- 需要把当天完成的工作压缩成日报。
- 需要面向不同读者生成两个版本：团队版和管理层版。
- 需要从工作记录中提炼结果、指标和阻塞，而不是流水账。

不适用：虚构未完成的工作、替用户承诺排期、把苦劳包装成结果。

## 输入

必需：

- 时间范围：本周起止日期，或日报的具体日期。
- 原始记录：任务列表、提交记录、会议要点、聊天摘要、工单状态。

可选：

- 读者：直属上级、跨部门、客户。
- 团队目标或 OKR。
- 可用指标：完成率、耗时、缺陷数、转化率、发布次数。
- 下周已知事项和休假安排。
- 期望长度：三行摘要、半页、完整周报。

缺失指标时不要编造。用定性结果替代，并标注「暂无数据」。

## 输出原则

1. **结果优先**：先写交付了什么、产生了什么影响，再写过程。
2. **可验证**：每条成果尽量带数字、版本、链接或验收状态。
3. **区分完成与进行中**：未完成的事项写清当前进度和剩余工作。
4. **风险前置**：需要上级决策或资源支持的事项单独列出。
5. **下周计划可执行**：每条都有目标和优先级，不写「继续推进」这种空话。
6. **读者适配**：管理层看结论和风险，团队看细节和协作请求。

## 工作流程

1. **确定周期和读者**：确认是日报还是周报、覆盖哪几天、给谁看。
2. **归并原始记录**：按项目或目标聚类，合并重复条目，删除无结果的忙碌记录。
3. **提炼成果**：每条写成「动作 + 结果 + 影响」；有数据时补上对比基线。
4. **标注进度**：完成、进行中、阻塞分别处理。进行中事项写百分比或剩余步骤。
5. **整理问题**：区分自己能解决的、需要协作的、需要上级决策的。
6. **规划下周**：按优先级列 3–5 项，每项写预期产出和依赖。
7. **压缩**：删掉形容词和过程细节，保留事实、数字和决策点。
8. **自检**：检查每条成果是否可验证，风险是否有明确求助对象。

## 输出格式

### 周报

```markdown
# 周报｜<姓名/团队>｜<开始日期>–<结束日期>

## 本周结论

<三句话以内：最重要的交付、最大的风险、最需要的支持。>

## 已完成

| 事项 | 结果 | 影响 / 数据 | 验收状态 |
|---|---|---|---|
| <事项> | <交付物> | <指标或影响> | <已上线/已验收/已合并> |

## 进行中

| 事项 | 当前进度 | 剩余工作 | 预计完成 |
|---|---|---|---|
| <事项> | <百分比或阶段> | <具体步骤> | <日期或待定> |

## 问题与风险

- **<问题>**：<影响>；需要 <谁> 在 <何时> 前 <做什么>。

## 下周计划

1. **<优先级 P0/P1/P2>** <事项>：<预期产出>；依赖 <依赖项>。
2. **<优先级>** <事项>：<预期产出>；依赖 <依赖项>。

## 需要支持

- <具体请求>，希望 <对象> 在 <时间> 前确认。
```

### 日报

```markdown
# 日报｜<日期>

## 今日完成

- <结果 1，带数据或验收状态。>
- <结果 2。>

## 进行中

- <事项>：<当前进度>，预计 <日期> 完成。

## 阻塞

- <阻塞描述>；需要 <谁> 支持 <具体动作>。

## 明日计划

- <最重要的 1–3 项。>
```

## 写作规则

- 一条只写一件事，避免「负责多个项目并推进若干事项」这类无法验证的表述。
- 用主动语态：「上线了 X」而不是「X 被推进」。
- 数字要带口径：百分比说明分母，时长说明统计范围。
- 未完成事项不写「基本完成」，写清剩余步骤。
- 风险写「影响 + 时间点 + 求助对象」，不写情绪。
- 同一事项在周报里只出现一次；跨项目协作放在「需要支持」。
- 日报控制在 15 行以内，周报控制在一屏到两屏。

## 不同读者的版本差异

- **管理层版**：结论、指标、风险、需要的决策；删掉技术细节。
- **团队版**：具体交付、接口变更、联调依赖、待补测试。
- **客户版**：只写已确认的进展和下一步，不暴露内部风险措辞。
- 同一条事实可以换措辞，但不能改变数字和承诺。

## 质量检查清单

- [ ] 时间范围明确。
- [ ] 每条成果都有结果，不只是动作。
- [ ] 数字有口径，没有编造。
- [ ] 进行中事项写清剩余工作。
- [ ] 风险有影响、时间点和求助对象。
- [ ] 下周计划不超过 5 项且有优先级。
- [ ] 全文没有「继续推进」「持续优化」这类空话。

## 边界

- 不虚构指标、客户反馈或上线时间。
- 不替团队承诺未确认的排期。
- 不把加班时长当作成果。
- 涉及客户名称、收入或未公开数据时，提醒用户确认披露范围。
