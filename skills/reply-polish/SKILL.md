# 客服 / 商务回复润色

## 何时使用

出现以下任一情况时使用本技能：

- 用户给出一段回复草稿，要求改得更专业、更有礼貌或更简短。
- 需要回复客户投诉、延期说明、报价询问或合作邀约。
- 需要把内部讨论转成对外邮件或即时消息。
- 需要同一事实的不同语气版本：正式邮件、即时消息、安抚回复。

不适用：替用户承认未确认的责任、承诺赔偿、或改写法律条款。

## 输入

必需：

- 原始草稿或要点。
- 回复对象：客户、合作方、同事、上级。
- 沟通目标：告知、道歉、拒绝、催办、报价、确认。

可选：

- 渠道：邮件、即时消息、工单、公开评论。
- 语气：正式、友好、克制、坚定。
- 不能承诺的边界：时间、金额、责任。
- 品牌称呼、署名和格式要求。
- 希望对方采取的下一步。

缺失关键事实时先问；不能问时用「待确认」占位，不自行补承诺。

## 润色原则

1. **先回应，再解释**：第一段直接回应对方最关心的事。
2. **事实准确**：不改数字、日期、责任归属和已确认的方案。
3. **承诺有边界**：只写已确认能做的事；不确定的写「确认后回复」。
4. **结构清楚**：一段一个目的，长回复用小标题或短列表。
5. **语气稳定**：不卑不亢，不用过度道歉，也不用强硬措辞。
6. **下一步明确**：谁在什么时候做什么，写清楚。
7. **删掉空话**：删除「非常抱歉给您带来不便」之类的套话堆叠，保留一次真诚回应。

## 工作流程

1. **识别真实诉求**：对方是在要答案、要补偿、要时间，还是要情绪安抚。
2. **核对事实**：把草稿中的数字、日期、承诺和责任人逐项对照输入。
3. **标记风险句**：找出可能构成承诺、归责或法律含义的句子。
4. **重排结构**：按「回应—说明—方案—下一步」重写。
5. **调整语气**：根据对象和渠道选择正式度；对外比对内更克制。
6. **压缩**：删除重复道歉、形容词和无关背景。
7. **输出对照**：给出润色稿、修改说明和需要用户确认的风险点。
8. **自检**：确认没有新增事实、没有扩大承诺、没有改变立场。

## 输出格式

```markdown
# 回复润色：<场景>

## 润色稿

<可直接发送的正文。>

## 修改说明

- <改动一>：<为什么这样改。>
- <改动二>：<...>

## 需要确认

- <风险句或缺失信息>：<建议如何确认。>

## 可选版本（如需要）

### 更简短

<压缩版。>

### 更正式

<正式版。>
```

## 常见场景模板

### 客户投诉

```text
您好，<称呼>：

关于您反馈的 <问题>，我们已确认 <事实>。给您带来的影响，我们表示歉意。

当前处理方案是 <已确认的动作>，预计 <时间> 完成。若 <条件>，我们会 <后续动作>。

下一步需要您 <配合事项>。如有疑问，可直接回复本消息。
```

### 延期说明

```text
您好，<称呼>：

原定 <日期> 交付的 <事项> 需要调整到 <新日期>。原因是 <已确认原因>，不是 <排除项>。

为减少影响，我们已 <补救动作>。新的交付范围是 <范围>，验收方式是 <方式>。

如这个时间影响您的安排，请在 <时间> 前告知，我们再评估替代方案。
```

### 拒绝请求

```text
您好，<称呼>：

感谢您提出 <请求>。经评估，我们目前无法按 <原方案> 推进，主要限制是 <客观原因>。

可以替代的方案是 <方案 A> 或 <方案 B>，各自的条件是 <条件>。

如果您希望推进，请确认优先方案，我们再给出具体排期。
```

### 报价询问

```text
您好，<称呼>：

根据您提供的 <需求范围>，初步报价为 <金额/区间>，包含 <交付项>，不含 <排除项>。

报价有效期至 <日期>。最终价格以 <确认条件> 为准。

如范围有变化，请补充 <信息>，我们会在 <时间> 内更新报价。
```

### 催办

```text
您好，<称呼>：

想确认 <事项> 的进展。该项目原计划 <日期> 完成，目前我们这边需要 <依赖项> 才能继续。

请在 <时间> 前回复 <具体信息>。如果时间需要调整，也请告知新的预期，方便我们同步相关方。
```

## 语气规则

- **正式邮件**：完整称呼、分段、结论在前、署名完整。
- **即时消息**：三到五句，先说要紧事，避免长段落。
- **公开评论**：不披露内部信息，不争论，引导到私下渠道。
- **安抚场景**：先承认影响，再给事实和方案；不重复空洞道歉。
- **强势场景**：用事实和边界表达坚定，不用威胁性措辞。

## 风险句检查

以下句子必须经过用户确认后才能保留：

- 明确的时间承诺：「我们会在周五前完成」。
- 金额或补偿：「退还全部费用」「赠送一个月」。
- 责任归属：「是我们的失误」「与贵方无关」。
- 排他或独家表述：「只为您保留」「不再向其他客户提供」。
- 法律含义：「双方达成一致」「最终解释权」。
- 数据披露：客户名称、合同金额、内部指标。

无法确认时改写为：「我们会在确认后第一时间回复具体时间」「补偿方案需要按合同条款评估」。

## 质量检查清单

- [ ] 第一段回应了对方最关心的问题。
- [ ] 数字、日期、责任和方案与原稿一致。
- [ ] 没有新增未确认的承诺。
- [ ] 每段只有一个目的。
- [ ] 下一步有对象、动作和时间。
- [ ] 语气与对象、渠道匹配。
- [ ] 删除了重复道歉和空泛套话。
- [ ] 风险句已单独列出等待确认。

## 边界

- 不替用户做法律、赔偿或合同解释。
- 不伪造已完成的处理动作。
- 不把客户投诉改写成对抗性表达。
- 涉及监管、诉讼、退款争议时，提示转交对应负责人。
